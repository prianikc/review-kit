# review-kit

Плагин Claude Code для работы с pull request'ами: ревью чужих PR воронкой агентов (A ищет ошибки, B — нарушения правил
проекта, C опровергает), разбор замечаний к своему PR и раунд правок. Повторное ревью учитывает историю: прошлые замечания и ответы автора.

Поддерживаются Forgejo и Gitea. Нужны Linux, macOS или WSL и git 2.38+.

## Установка

```
/plugin marketplace add prianikc/review-kit
/plugin install review-kit@review-kit
```

Токен — переменная окружения `FORGEJO_TOKEN` (или `GITEA_TOKEN`), заданная в профиле shell (`~/.bashrc`, `~/.zshrc`).

Репозиторий определяется по `git remote get-url origin`. Для нестандартного remote — `.claude/review-kit.local.json`:

```json
{ "provider": "forgejo", "host": "git.example.org", "owner": "team", "repo": "app" }
```

Других плагинов и программ не нужно.

## Обновление

```
claude plugin marketplace update review-kit
claude plugin update review-kit@review-kit
```

Что вошло в каждую версию — в [Releases](https://github.com/prianikc/review-kit/releases).

## Команды

| Команда | Что делает |
|---|---|
| `/pr` | список открытых PR со статусами (с пометкой «конфликт»): «на проверку» — дело за вами, «ожидающие решения» — за другими |
| `/pr N` | сценарий для PR N по его статусу: ревью чужого PR (с учётом истории: закрытые автором замечания не повторяются, незакрытые приходят follow-up), разбор замечаний к своему, слияние базы при конфликте |
| `/pr N review` | ревью PR N без выбора по статусу — например, отчёт по своему или влитому PR |
| `/pr N feedback` | разбор замечаний к своему PR и ответы: пока агент разбирает — все замечания PR, после — итог по каждому с причиной |
| `/pr N fix` | раунд правок своего PR: план (Plan Mode), правки, проверка, diff в чате, commit и push |
| `/pr stop` | закрыть идущий прогон |
| `/pr-confl N` | влить базу в свой PR N, разрешить конфликты, commit и push |
| `/guide N\|коммит` | краткий гайд по PR или коммиту: описание, коммиты, что сделано, узкие места; в ревью показывается сразу после старта, пока работают агенты |

Уборка — только за собой: после ревью чужого PR удаляются ветка ревью и его worktree, основное дерево возвращается на
ветку, где было до ревью, и ваш stash применяется. Брошенные прогоны, старые гайды и законченные worktree ревью
убираются молча при следующем `/pr`.

## Скиллы

| Скилл | Когда срабатывает |
|---|---|
| `pr-flow` | просьба словами: «посмотри PR 140», «есть что ревьюить?» |
| `pr-confl` | `/pr-confl N`, «PR 140 в конфликте» — слияние базы в свой PR |
| `guide` | `/guide 140`, `/guide 3edsf3a`, «что в этом PR»; зовут ревью, другие скиллы и агенты |

Внутренние скиллы прогона (`pr-review-run`, `pr-publish-run`, `pr-feedback-run`, `pr-fix-run`, `pr-replies-run`)
запускает `/pr`, в меню их нет.

## Расширения

Другой плагин может добавить к киту свои возможности, не трогая его:

- **способ публикации ревью** — скилл с описанием `review-kit extension: publish — <Имя>. …` появляется вариантом
  `<Имя>` в вопросе «Как публикуем?»; публикует он через `review_publish` с `source`, и кит всё равно спрашивает «Да/Нет»;
- **проверка правок перед push** — скилл с описанием `review-kit extension: fix review — <Имя>. …` появляется вариантом в
  вопросе «Правки перед push»;
- **ревью в отдельных деревьях** — инструмент `review_worktree` создаёт worktree ревью и отдаёт команду для запуска в
  каждом; терминал открывает расширение.
