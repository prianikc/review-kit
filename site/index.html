Плагин Claude Code · v3.7.0

Ревью pull request'ов воронкой агентов

Один агент ищет ошибки, второй — нарушения правил проекта, третий пытается их опровергнуть. До вас доходит только то, что выдержало спор. А ещё — разбор замечаний к своему PR, раунд правок и перепроверка, не выходя из Claude Code.

Установить Как это работает
claude
> /plugin marketplace add prianikc/review-kit
> /plugin install review-kit@review-kit

// зачем

Четыре сценария вокруг одного PR

review-kit сам определяет, чей это PR и что с ним сейчас, и предлагает нужный сценарий.

⌕

Ревью чужого PR

Воронка агентов A/B → C прогоняет diff, вы видите отчёт с уровнями и вердиктом и публикуете его одним подтверждением — целиком или выборочно.

/pr-review N
↻

Перепроверка

После правок автора — что из ваших замечаний исправлено, что нет, и нет ли нового в дельте с прошлого ревью. Влитая база не засоряет diff.

/pr-recheck N
✉

Разбор замечаний

Агент D раскладывает комментарии к вашему PR: что править, о чём спорить, что уже сделано. Ответы уходят в треды только после вашего «да».

/pr-feedback N
✎

Раунд правок

План в Plannotator, правки, проверка агентом, commit и push — по шагам и с подтверждением на каждом внешнем действии.

/pr-fix N

Воронка, которая спорит сама с собой

Большинство «умных» ревью шумят. Здесь каждая находка проходит через оппонента и порог уверенности, прежде чем попасть в отчёт.

  1. A correctness
    B quality

    Поиск

    A ищет ошибки в логике, B — нарушения правил проекта из CLAUDE.md и .claude/rules/. Работают параллельно. Находка без сценария отказа отбрасывается сразу.

  2. C refuter

    Опровержение

    C пытается доказать, что находка ложная. Итог — confirmed, cannot-refute или отказ, плюс уверенность в процентах.

  3. порог

    Порог

    critical и important проходят от 75%, minor — от 85%. Подтверждённое ниже порога видно в отчёте, но никогда не публикуется.

  4. вы

    Решение

    Отчёт в чате или аннотациями в Plannotator. Публикация, ответы и push — только после вашего подтверждения в диалоге.

Уровни находок

critical
ломает продукт, теряет данные или эксплуатируемо
important
измеримая регрессия, конкретный риск или нарушение правила проекта
minor
стиль, имена, предпочтения

Вердикт

Blocked
есть critical
Changes requested

Approved
находок нет
  • Без сюрпризов. Внутри прогона сырые git push и curl заблокированы — внешние действия идут только через инструменты плагина с подтверждением.
  • Без потерь. Ветки, stash и worktree удаляются только явной командой /pr cleanup.
  • Честный отчёт. Раздел «Не проверялось» есть всегда: что не смотрели и сколько находок отброшено и почему.

// установка

Три шага до первого ревью

Linux · macOS · WSL git ≥ 2.38 Node 24 Claude Code Forgejo / Gitea
  1. 1

    Поставьте плагин

    В Claude Code добавьте маркетплейс и установите плагин.

    /plugin marketplace add prianikc/review-kit
/plugin install review-kit@review-kit
  2. 2

    Дайте токен

    Токен Forgejo или Gitea — переменная FORGEJO_TOKEN (или GITEA_TOKEN) в профиле shell: ~/.bashrc или ~/.zshrc. Перезапустите терминал.

    echo 'export FORGEJO_TOKEN=<ваш токен>' >> ~/.bashrc
  3. 3

    Откройте проект и запустите

    Репозиторий определяется по git remote get-url origin. Наберите /pr — появится список открытых PR со статусами и выбор сценария.

    /pr

Нестандартный remote

+

Если хост или путь не угадываются по origin, положите в проект .claude/review-kit.local.json:

{ "provider": "forgejo", "host": "git.example.org", "owner": "team", "repo": "app" }

Дополнительные плагины

+
  • Plannotator и superpowers — для раунда правок /pr-fix и просмотра находок аннотациями.
  • Orca — чтобы открывать ревью в отдельных вкладках и worktree (/pr all, параллельные ревью).

Без них ревью, перепроверка и разбор замечаний работают в текущей вкладке.

Обновить до свежей версии

Плагин обновляется, когда в репозитории поднимается версия. Выполните в терминале и перезапустите Claude Code.

$ claude plugin marketplace update review-kit

// команды

Всё начинается с /pr

Можно и словами: «посмотри PR 140», «есть что ревьюить?». stop вместо номера (/pr-review stop) закрывает идущий прогон.

/pr [N]

открытые PR со статусами (с пометкой «конфликт») и выбор сценария; с номером — сразу сценарий для PR N

/pr all

все PR, по которым есть дело, — каждый во вкладке Orca

/pr cleanup

убрать ветки, stash и worktree законченных ревью

/pr-review N

ревью чужого PR

/pr-recheck N

перепроверка чужого PR после своего ревью

/pr-feedback N

разбор замечаний к своему PR и ответы

/pr-fix N

раунд правок своего PR: план, правки, проверка, commit и push

/pr-view

открыть находки идущего ревью в Plannotator

/commit [all] [текст]

коммит файлов сессии (или всех с all) с придуманным сообщением

/confl [N]

разрешить конфликты в дереве; с номером — влить базу в свой PR N, разрешить, commit и push

/push

запушить текущую ветку и показать ссылку на PR

/merge [ветка]

влить свежий main (или указанную ветку) в текущую, конфликты — через /confl; не пушит

/gsync

подтянуть с origin: перемотать main, текущую и остальные ветки; отчёт по отставшим, разошедшимся и удалённым
